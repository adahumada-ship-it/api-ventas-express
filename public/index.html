Documentación de la API de Ventas

Consulta ventas por identificador, obtén un consolidado por sucursal y año, o registra una nueva venta desde tu aplicación.

URL base localhttp://localhost:3000/api/v1/ventas

Conexión y formato

La API acepta y devuelve JSON. Sustituye el host y puerto por los de tu entorno cuando esté desplegada.

Base URLhttp://localhost:3000/api/v1/ventas en desarrollo.
AutenticaciónNo se configura autenticación en los endpoints actuales.
CabecerasPara enviar un cuerpo, usa Content-Type: application/json.

Endpoints

Todos los recursos están bajo el prefijo /api/v1/ventas.

GET/consolidado

Devuelve el consolidado de ventas filtrado por sucursal y año. Ambos parámetros de consulta son obligatorios.

Parámetros de consulta

ParámetroTipo esperadoRequeridoDescripción
sucursalTexto o identificadorSíSucursal para filtrar el consolidado.
anioAñoSíAño para el que se solicita el consolidado.
Solicitud · cURL
curl "http://localhost:3000/api/v1/ventas/consolidado?sucursal=Centro&anio=2025"

Respuesta exitosa · 200

application/json
{
  "status": "sucess",
  "total_registros": 1,
  "data": [ /* filas devueltas por el procedimiento de consolidado */ ]
}
El nombre de estado que devuelve actualmente este endpoint es sucess (con esa ortografía). La estructura de cada fila depende del procedimiento almacenado de la base de datos.
GET/:id_venta

Busca una venta por su identificador único.

Parámetro de ruta

ParámetroTipoRequeridoDescripción
id_ventaEntero positivoSíIdentificador de la venta que se desea consultar.
Solicitud · JavaScript
const response = await fetch(
  'http://localhost:3000/api/v1/ventas/42'
);
const result = await response.json();
console.log(result);

Respuesta exitosa · 200

application/json
{
  "status": "success",
  "data": [ /* venta devuelta por la base de datos */ ]
}
POST/

Registra una venta nueva. Envía los cuatro campos obligatorios en el cuerpo JSON.

Cuerpo de la solicitud

CampoTipo esperadoRequeridoDescripción
id_productoIdentificadorSíProducto vendido.
id_clienteIdentificadorSíCliente que realiza la compra.
cantidadNúmeroSíCantidad vendida.
fecha_ventaFechaSíFecha de la venta; se recomienda formato YYYY-MM-DD.
Solicitud · cURL
curl -X POST "http://localhost:3000/api/v1/ventas" \
  -H "Content-Type: application/json" \
  -d '{
    "id_producto": 12,
    "id_cliente": 7,
    "cantidad": 2,
    "fecha_venta": "2025-04-18"
  }'

Respuesta exitosa · 201

application/json
{
  "status": "created",
  "message": "venta registrada exitosamente",
  "datos_registrados": {
    "id_producto": 12,
    "id_cliente": 7,
    "cantidad": 2,
    "fecha_venta": "2025-04-18"
  }
}

Respuestas y errores

Los errores se devuelven como JSON. Revisa el código HTTP además del cuerpo.

  • 200Consulta completada correctamente.
  • 201Venta creada correctamente.
  • 400Faltan parámetros o el identificador de venta no es un entero positivo.
  • 404No existe una venta con el identificador solicitado.
  • 500Error interno al consultar o escribir en MySQL.
Ejemplo · error de validación
{
  "error": "Bad Request",
  "message": "Debe enviar ambos parametros"
}
La API necesita una conexión válida a MySQL y los procedimientos almacenados requeridos para operar. No se ha configurado CORS en el servidor; si el cliente web está en otro origen, el servidor deberá habilitarlo.
